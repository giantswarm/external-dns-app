# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Giant Swarm Helm chart (`helm/external-dns-app`) wrapping the upstream [external-dns](https://github.com/kubernetes-sigs/external-dns) chart. It is deployed to Workload Clusters as a default app and as a managed app, and can be installed multiple times in one cluster.

## Upstream sync model

The chart is not edited by hand. It is generated from upstream plus local patches:

1. `vendir.yml` pins the upstream chart version. `vendir sync` pulls it into `vendor/external-dns` and copies it into `helm/external-dns-app` (except `Chart.yaml`, `Chart.lock` and `README.md*`, which are ours).
2. `sync/sync.sh` runs `vendir sync`, then every `sync/patches/<area>/patch.sh` in order, then `make helm-docs`, and finally regenerates `diffs/` (one `.patch` per file that differs from upstream).
3. CI (`.github/workflows/validate-sync-diffs.yaml`) runs `./sync/sync.sh` and fails on any `git diff`. Any change under `helm/external-dns-app` must therefore be backed by a patch in `sync/patches`, and `sync.sh` output (including `diffs/`) must be committed.

Patch conventions:
- Reuse the existing `sync/patches/<area>/` that already modifies a file instead of creating a new area and script for it. For example, a change to `_helpers.tpl` goes into `sync/patches/helper`, not a new `sync/patches/<something>/patch.sh`.
- Template changes are numbered git patches applied with `git apply` in the area's `patch.sh` (e.g. `sync/patches/helper/000-helper.patch`, `001-...`). Add a new numbered patch on top of the existing ones instead of rewriting earlier patches, and avoid ad-hoc `sed`/`perl` scripts.
- Files that we fully own (`values.yaml`, `values.schema.json`, `np.yaml`, `vpa.yaml`, `crds.yaml`) are copied wholesale from `sync/patches/<area>/`, so edit them there, not in `helm/`.
- Upstream CRDs are moved to `helm/external-dns-app/files`. `templates/crds.yaml` installs them.

To bump upstream, change the version in `vendir.yml` and run `./sync/sync.sh`. Fix any patch that no longer applies.

## Commands

```sh
./sync/sync.sh                                     # regenerate chart + diffs (needs vendir, docker for helm-docs)
make helm-docs APPLICATION=external-dns-app        # regenerate helm/external-dns-app/README.md from README.md.gotmpl
make lint-chart APPLICATION=external-dns-app       # ct lint (needs architect + docker)
helm template helm/external-dns-app -f tests/test-values.yaml   # quick render check
```

Tests:
- `tests/e2e`: Go/Ginkgo suites using `apptest-framework` (`suites/basic`, run on CAPA per `tests/e2e/config.yaml`), triggered in CI through Tekton. They need a real test cluster and are not run locally.
- `tests/ats`: legacy app-test-suite (pytest) smoke/upgrade tests on kind, configured in `.ats/main.yaml` with `tests/test-values.yaml`.

## Conventions

- Update `CHANGELOG.md` under `[Unreleased]` for user-facing changes (CI validates the changelog). Skip it when the rendered chart does not change.
- Conventional commit PR titles (validated by CI).
- Files prefixed `zz_generated` and the `Makefile*` are generated by devctl, so do not edit them.
- Release: push a branch named `main#release#vX.Y.Z` from main.
- `docs/upgrading.md` documents the v3 breaking changes. Keep it in sync if value semantics change.
